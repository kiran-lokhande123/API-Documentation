2. Understand the endpoint
Our endpoint is:
/employees/{employeeId}


What does {employeeId} mean?

It is a path parameter.

It represents a variable value that the application supplies when making the API request.

For example:
Endpoint	Employee ID
/employees/EMP1001	EMP1001
/employees/EMP1002	EMP1002
/employees/EMP1003	EMP1003

Why do we use a path parameter?

Because the API needs to know which employee the application wants to retrieve.

Compare our first two endpoints:
- GET /employees – Retrieves all employees.
- GET /employees/{employeeId} – Retrieves one specific employee.
3. Add the second endpoint to YAML
Open employee-api.yaml.

Under the existing paths section, add this endpoint. Make sure it has the same indentation as /employees.
  /employees/{employeeId}:
    get:
      summary: Retrieve an employee by ID
      description: Retrieves employee details using the employee ID.
      operationId: getEmployeeById

      parameters:
        - name: employeeId
          in: path
          required: true
          description: Unique identifier of the employee.
          schema:
            type: string
          example: EMP1001

      responses:
        '200':
          description: Employee retrieved successfully.
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/Employee'
              example:
                employeeId: EMP1001
                firstName: John
                lastName: Smith
                email: john.smith@example.com
                department: Engineering

        '404':
          description: Employee not found.


Important: Add this under paths, not under components.
4. Understand the new YAML elements
We have already covered get, summary, description, operationId, and responses. Let's focus on the new elements.

A. parameters

Defines the input values that an API operation needs.

In our example, the API needs an employee ID.

B. name: employeeId

Specifies the name of the parameter.

C. in: path

Tells OpenAPI that this parameter is part of the URL path.

Other common parameter locations include:
Location	Purpose
path	Value included in the URL path
query	Optional value added after ? in a URL
header	Value sent in the HTTP request header
cookie	Value sent through a cookie

D. required: true

Means the employee ID must be supplied.

A path parameter is always required in OpenAPI.

E. schema: type: string

Specifies that the employee ID is text.

F. example: EMP1001

Provides a sample employee ID so developers understand what value to supply.

G. 404

HTTP status code 404 means the requested employee was not found.

For example, if the application requests EMP9999 and no such employee exists, the API may return this status code.
