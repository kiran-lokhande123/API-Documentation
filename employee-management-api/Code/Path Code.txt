4. Understand the new YAML elements
Let's understand the important parts.

A. get

Defines the HTTP method used by this endpoint.

B. summary

Provides a short description of the operation. Swagger UI displays this prominently.

C. description

Provides additional information about what the endpoint does.

D. operationId

Provides a unique identifier for this API operation.

For example, getEmployees identifies the operation that retrieves all employees. It can also be used by tools that generate client code.

E. responses

Defines what the API returns after processing the request.

Here, we have documented HTTP status code 200.

F. 200

HTTP status code 200 means the request was successful.

G. content

Specifies the format of the response data.

We use:
application/json:


This tells the reader that the response is returned in JSON format.

H. schema

Describes the structure and data types of the response.

We have used:
type: array


Why an array?

Because this endpoint returns multiple employees, not just one employee.

And:
items:
  $ref: '#/components/schemas/Employee'


This tells OpenAPI that each item in the array follows the Employee schema.

We'll define that schema in our next step.

I. example

Provides sample response data so developers can understand what the API returns.
